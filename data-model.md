# Data model

SQLite, one file, migrated on startup with `CREATE TABLE IF NOT EXISTS`. Integer cents. Timestamps are ISO-8601 strings with offset, stored as text. The demo timezone is `America/Los_Angeles`.

## shares

| Column | Type | Notes |
|---|---|---|
| `id` | text pk | `shr_` plus 12 hex chars |
| `contract_id` | text not null | FK |
| `display_name` | text not null | |
| `is_grace_subject` | integer not null | 0 or 1 |
| `status` | text not null | See `architecture.md` |
| `amount_cents` | integer not null | Copy of `share_cents` |
| `money_source` | text not null | `sample` or `sandbox` |
| `order_id` | text null | PayPal order id |
| `capture_id` | text null | PayPal capture id |
| `refund_id` | text null | PayPal refund id |
| `order_idempotency_key` | text not null | `order:{contractId}:{shareId}` |
| `capture_idempotency_key` | text not null | `capture:{contractId}:{shareId}` |
| `refund_idempotency_key` | text not null | `refund:{contractId}:{shareId}` |
| `sample_label` | text null | Required when `money_source = sample` |
| `created_at` | text not null | |
| `updated_at` | text not null | |

Unique index on `order_idempotency_key`, `capture_idempotency_key`, and `refund_idempotency_key`.

`sample` rows must have null `order_id`, `capture_id`, and `refund_id`. `sandbox` rows may have null ids until the corresponding call succeeds. A `sandbox` row with status `captured`, `locked`, or `refunded` must have the matching PayPal id.

## paypal_operations

One row per attempt to call PayPal. This is the audit log and the unknown-outcome record.

| Column | Type | Notes |
|---|---|---|
| `id` | text pk | `op_` plus 12 hex chars |
| `share_id` | text not null | |
| `kind` | text not null | `create_order`, `capture`, `refund`, `sync` |
| `idempotency_key` | text not null | The stable key for that kind |
| `request_json` | text not null | Amounts and ids. No access token |
| `response_status` | integer null | HTTP status, null on transport failure |
| `response_json` | text null | Body or error text, truncated at 8000 chars |
| `outcome` | text not null | `completed`, `failed`, `unknown` |
| `created_at` | text not null | |

Before starting a `create_order`, `capture`, or `refund`, insert the operation row in a transaction with the share status change to `checkout_open`, `capture_unknown`, or `refund_pending`. If the process dies mid-call, startup does not guess. The next `sync` or the same route sees the open operation and returns `409 money_unknown` instead of sending a second mutating call.

A completed capture or refund with the same idempotency key is replayed from the stored PayPal id. It is not sent again.

## events

Append-only, for the reason panel and tests.

| Column | Type | Notes |
|---|---|---|
| `id` | integer pk | autoincrement |
| `contract_id` | text not null | |
| `share_id` | text null | |
| `type` | text not null | Listed below |
| `detail` | text not null | Human sentence |
| `created_at` | text not null | Uses `demo_now` when the cause is the clock, otherwise wall time |

Event types: `rule_extracted`, `clarification_requested`, `rule_confirmed`, `order_created`, `capture_completed`, `capture_unknown`, `checkout_declined`, `grace_started`, `share_expired`, `refund_completed`, `refund_unknown`, `contract_locked`, `contract_unwound`, `contract_blocked`, `clock_moved`.

## Demo-prepared sandbox rows

Not inserted by the default seed. `demo.md` describes the prep steps that create a third and fourth contract with `money_source = sandbox` and real ids. Until prep runs, the app still opens on the two sample contracts.

## Reset

`POST /api/demo/reset` deletes `events`, `paypal_operations`, `shares`, and `contracts`, then inserts the two sample contracts. It does not call PayPal. The response includes `paypal_leftovers: true` as a constant reminder string field `warning`: "Local rows were cleared. Sandbox captures that already happened are still in PayPal until you refund them."

## Migration rule

Ship the full schema in phase 1. Later phases fill columns; they do not add tables. If an implementation believes a column is missing, stop and check this file rather than altering the database ad hoc.
